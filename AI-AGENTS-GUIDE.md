# AI Agents System - Implementation Guide

## Overview

This project now includes an **Agentic AI System** that provides autonomous intelligence across your microservices architecture. The agents can perceive, reason, and act independently to enhance system reliability, security, and efficiency.

## Implemented AI Agents

### 1. **Anomaly Detection Agent** 🔍
**Location:** `common/src/main/java/com/example/common/ai/agents/AnomalyDetectionAgent.java`

**Capabilities:**
- Detects suspicious user creation patterns in real-time
- Multi-criteria anomaly scoring (email patterns, rapid creation, domain reputation)
- Automatic quarantine of high-risk users
- Flags suspicious accounts for review

**Detection Criteria:**
- Suspicious email patterns (test123, temp456, bot, spam, fake)
- Rapid account creation (>5 accounts per minute from same email)
- Unusual username patterns (all numbers, repeated characters, low vowel ratio)
- Temporary email domains (tempmail.com, mailinator.com, etc.)
- Missing critical user information

**Actions:**
- `ALLOW`: Normal user, proceed with email
- `FLAG_FOR_REVIEW`: Create low-priority Jira ticket
- `QUARANTINE`: Block user, create critical security ticket, skip email

**Example Usage:**
```java
AgentDecision decision = anomalyDetectionAgent.process(userCreatedEvent);
if ("QUARANTINE".equals(decision.getAction())) {
    // User is quarantined
    logger.warn("User quarantined: {}", decision.getReasoning());
}
```

### 2. **Jira Intelligence Agent** 🎫
**Location:** `common/src/main/java/com/example/common/ai/agents/JiraIntelligenceAgent.java`

**Capabilities:**
- AI-powered Jira ticket generation
- Intelligent priority assignment (Critical/High/Medium/Low)
- Smart team assignment based on issue type
- Effort estimation
- Automatic label generation
- Contextual descriptions with recommended actions

**Ticket Types:**
- `USER_ANOMALY`: Security issues → security-team
- `SERVICE_FAILURE`: System failures → devops-team
- `PERFORMANCE_ISSUE`: Performance degradation → performance-team
- `DATA_QUALITY`: Data issues → data-team

**Example Generated Ticket:**
```

Priority: Critical
Assignee: security-team
Estimated Effort: 4-8 hours
Labels: [ai-generated, user-anomaly, automated-detection, high-confidence]

*Automatically generated by AI Agent*

h3. Issue Summary
Suspicious user account detected...

h3. Recommended Actions
# Review user account details
# Check recent activity logs
# Verify email domain reputation
# Consider account suspension if confirmed malicious
```

### 3. **Self-Healing Agent** 🔧
**Location:** `common/src/main/java/com/example/common/ai/agents/SelfHealingAgent.java`

**Capabilities:**
- Continuous service health monitoring
- Automatic failure detection
- Pattern-based remediation triggering
- Tracks consecutive failures
- Auto-restart for critical issues

**Health Checks:**
- Error rate monitoring (>10% = Critical, >5% = Warning)
- Response time analysis (>5000ms = Warning)
- Service availability checks
- Consecutive failure tracking (≥3 = Critical)

**Remediation Actions:**
- `MONITOR`: Normal operation
- `TRIGGER_REMEDIATION`: Manual intervention suggested
- `AUTO_RESTART`: Automatic service restart initiated

**Example Health Check:**
```java
ServiceHealthCheck check = new ServiceHealthCheck(
    "evaluation-service", 
    true,      // service up
    0.02,      // 2% error rate
    350.0      // 350ms avg response time
);

AgentDecision decision = selfHealingAgent.process(check);
```

### 4. **Smart Routing Agent** 🔀

**Capabilities:**
- Intelligent message routing based on content

**Note:** Currently implements rule-based routing; can be enhanced with ML models for learning optimal routing patterns.

## Configuration

Add to `application.yaml`:

```yaml
# AI Agents Configuration
ai:
  agents:
    anomaly-detection:
      enabled: true
      threshold: 0.7
    jira-intelligence:
      enabled: true
    self-healing:
      enabled: true
      failure-threshold: 3
    smart-routing:
      enabled: true
```

To disable an agent:
```yaml
ai:
  agents:
    anomaly-detection:
      enabled: false
```

## Agent Architecture

### Base Framework
All agents extend `BaseAgent` which provides:
- Common initialization and configuration
- Decision tracking and metrics
- Learning from feedback
- Error handling
- Status reporting

### Agent Lifecycle
1. **Initialize**: Load configuration, set up state
2. **Process**: Receive input, analyze, make decision
3. **Learn**: Receive feedback, adjust behavior
4. **Monitor**: Report status and metrics
5. **Shutdown**: Clean up resources

### Agent Decision Structure
```java
AgentDecision {
    String agentName;           // Which agent made decision
    String action;              // Action to take (ALLOW, QUARANTINE, etc.)
    double confidence;          // Confidence score (0.0 - 1.0)
    String reasoning;           // Human-readable explanation
    Map<String, Object> params; // Additional context
    boolean requiresApproval;   // Needs human review?
    LocalDateTime timestamp;    // When decision was made
}
```

## Troubleshooting

**Agents not starting:**
- Check `ai.agents.*.enabled` configuration
- Verify `@ComponentScan` includes `com.example.common.ai`
- Check logs for initialization errors

**Anomaly detection too sensitive:**
- Adjust threshold in configuration (default: 0.7)
- Tune individual criteria weights in code
- Add whitelist for known good patterns

**Self-healing not triggering:**
- Verify health check input values
- Check failure threshold configuration
- Review service metrics accuracy
